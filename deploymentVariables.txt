# Deployment variables and secrets

GitHub secrets are write-only. This inventory records names, scope, and
provenance without exposing secret contents. The current workflow deploys a
merged `develop` branch to `test` and `release` to `production`; database name,
port, TLS mode, and backend port are selected by the workflow.

## Required GitHub Environments

Create `test` and `production` under Repository Settings → Environments before
deploying. The workflow requires environment-scoped `DEPLOY_HOST`,
`DEPLOY_USER`, and `DEPLOY_SSH_KEY_B64`; it will fail before SSH if they are
missing. Production should require an approval reviewer.

The current GitHub CLI identity lacks repository-admin permission to create
environments. Consequently, the existing production runtime variables are
still at repository scope until an administrator creates the environments and
migrates them. The current environment list contains only `bingo-backend-production`
and `copilot`; the unused secret was removed from the former. Do not deploy
until `test` and `production` exist and their settings are configured. The
former `LIGHTSAIL_*` deployment secrets are no longer consumed.

delete the old secrets. Create/revoke API keys in App Store Connect as needed.

## Backend secret status

The canonical backend runtime secrets are `MYSQL_PASSWORD`, `JWT_SECRET`,
`BINGO_FLOAT_BANK_ENCRYPTION_KEY`, and the selected email provider credentials.
They are currently configured at repository scope; set separate values in
both GitHub Environments. `SPRING_MAIL_PASSWORD` is not currently configured;
it is required only when SMTP is selected.

| Existing secret name | State |
|---|---|

The duplicate `GRAPH_*`, `BINGO_GOOGLE_PLAY_SERVICE_ACCOUNT_JSON_BASE64`,

## Setup commands

Create a dedicated unencrypted SSH key pair and install its public key on the
corresponding host:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/bingo-deploy -C bingo-deploy
base64 -i ~/.ssh/bingo-deploy | tr -d '\n' | gh secret set DEPLOY_SSH_KEY_B64 --repo equar/bingo-platform --env test
```

Use the test `web_static_ip` output as `DEPLOY_HOST`; set production host and
user values from the production server configuration. Configure each
environment at Repository Settings → Environments before setting secrets.

Create an encryption key once per environment and preserve a secure backup:

```bash
openssl rand -base64 32
openssl rand -hex 32
```

The first command produces a 32-byte bank-encryption key; the second produces
a 32-byte JWT secret. Do not reuse the production values in test. Use the
environment importer after creating both environments:

```bash
GH_ENVIRONMENT=test bash deployment/aws/bootstrap-github-actions-config.sh deployment/aws/github-actions-test.env
GH_ENVIRONMENT=production bash deployment/aws/bootstrap-github-actions-config.sh deployment/aws/github-actions-prod.env
```

For store credentials, upload the Google service-account JSON with
`gh secret set GOOGLE_PLAY_JSON < /path/to/google-play-service-account.json`.
Generate the App Store Connect bundle as described in
`deployment/mobile/README.md` and upload it with
`gh secret set APPSTORE_DEPLOYER_KEY < /path/to/appstore-deployer-key.json`.
Do not print secrets, commit credential files, or place real values in examples.
