## Cross-cutting configuration and database map

- Main/dev backend defaults are `application.yml` and `application-dev.yml`; the dev datasource defaults to catalog `bingo`, `createDatabaseIfNotExist=true`, and Hibernate `update`. Do not use it for QA.
- Persistent QA uses `application-qa.yml`, `bingo_qa`, Hibernate `validate`, Flyway `clean-disabled=true`, and `.env.qa` placeholders.
- Android/Admin integration runtime uses `application-android-test.yml`, `BINGO_TEST_MYSQL_*`, `bingo_qa_test`, Hibernate `validate`, and Flyway clean disabled. The project owner accepts the schema-scoped local grant for this test environment; it is not production authorization or permission for cross-schema access. See the local-only exception in the [guarded E2E runbook](platform-e2e-runbook.md).
- Maven test config uses `application-test.yml`, `BINGO_MAVEN_MYSQL_*`, and exact local `bingo_qa_maven_test` / `bingo_qa_maven_runner` policy. The local Maven schema/account remain unprovisioned. `A00FlywayUpgradeRecoveryIntegrationTest` calls `Flyway.clean()` and is safe only in the dedicated disposable database after its guard.
- Legacy test notes used a separate `bingo_test` database and destructive drop commands; these are not current setup instructions. Current Maven tests are guarded to the disposable `bingo_qa_maven_test` target and functional E2E uses the separate `bingo_qa_test` schema. Never run generic drop/clean commands or target persistent/shared databases; follow the current isolation and recovery procedures.
- Financial flags default off. Synthetic positive posting needs explicit isolated Maven opt-in. Prize settlement always fails closed. No claim/domain behavior authorizes production financial posting.
- `.env.test`, `.env.qa` and Maven secrets are local ignored configuration; existing evidence intentionally redacts values. A prior local test credential exposure and rotation/provisioning blockers are recorded in the 04C-5A/5B reports; never copy values into tracked evidence.

See [blockers and approvals](qa-blockers-and-approvals.md) for current conditions. No source functionality or historical evidence was changed by this inventory.

## Coverage status interpretation

- **PASS** is reserved for the cited scenario/result in its source report; it is not inherited by unrun scenarios in the same domain.
- **BLOCKED** means a named approval, policy, environment or safe fixture is missing. **NOT RUN** means it was not executed; **N/A** means the scenario does not apply to the identified implementation.
- L5 examples are explicitly scoped. They do not close Module 02, 04B, 04C or 04D globally, and they do not imply live financial settlement.
- Current execution status is in the [scenario matrix](platform-e2e-scenario-matrix.md)
and [blockers register](qa-blockers-and-approvals.md). The historical module
summaries have been consolidated; retained run evidence remains under
`docs/qa/evidence/`.
