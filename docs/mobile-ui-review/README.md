# Player app responsive UI review

The changes preserve the existing home artwork, blue/orange palette, feature cards,
labels, navigation destinations, APIs, and game/payment rules. Scope is `bingo-player`;
the separate agent app is unchanged.

## Layout and accessibility

- Phone navigation stays at the bottom. At 840 logical pixels wide and 480 high,
  navigation moves to a side rail. Smaller landscape layouts keep phone navigation.
- Single-column screens use an 840-pixel content limit; the app canvas stops at
  1200 pixels. Landscape safe areas protect content from notches and system edges.
- Home cards switch to one column below 300 pixels of available content width or
  above approximately 1.43x text scaling. System text scaling is not globally capped.
- Inputs use visible outlines, focus borders, multiline validation errors, and
  consistent padding. Buttons retain at least 48 logical pixels of touch height.
  Primary blue and filled-button orange are deeper for readable foreground contrast.
- Deposit dialogs, menus, and status messages scroll in short viewports. Wallet
  tabs scroll horizontally; action groups and pagination wrap instead of overflowing.
  Wallet history height follows the screen instead of always consuming 560 pixels.
- Ticket labels fit inside board cells. Draw animation and navigation transitions
  respect the system reduced-motion setting.

## Loading and usability

Home artwork is decoded for the displayed width and device pixel ratio, capped at
its source width, instead of always decoding the full image on small devices. A
static placeholder avoids a blank hero while it loads. Home cards no longer use
intrinsic-height layout passes. Existing lazy data lists remain lazy. No new
packages, custom runtime font downloads, polling, or startup API calls were added.

The review also fixed community refresh callbacks returning a Future from setState,
retrying failed room templates without losing the form, refreshing private game
state on return, stale leaderboard pagination during loading, and join-dialog
back dismissal while a request is pending. Invite completion stops the background
busy animation before showing the invite. Login now has a localized PIN visibility
toggle without changing the PIN or login rules.

## Validation

Final local validation: **97 tests passed**, and **Flutter analysis: no issues**
using Flutter 3.41.2 / Dart 3.11. The original lockfile is retained; no dependency
changes are part of this work.

[Phone preview](phone.png) · [Tablet preview](tablet.png). These are widget-rendered
previews using local preview fonts, not screenshots from physical devices.

Widget coverage includes 320×568, 390×844, 844×390, and 1024×768 logical-pixel
viewports; 1x/2x text; Amharic at 320 pixels and 2x text; tablet navigation;
keyboard-visible deposits; scrollable status actions; and narrow-screen wallet
pagination/transfers. Existing authentication, community, localization, wallet,
and live-game tests are included in the full suite.

```sh
cd bingo-player
flutter pub get
flutter gen-l10n
flutter analyze
flutter test
```

Optional preview output can be generated by running `test/responsive_ui_test.dart`
with `--dart-define=UI_PREVIEW_DIR=/your/output/path`. Optional
`UI_PREVIEW_TEXT_FONT` and `UI_PREVIEW_ICON_FONT` defines accept local font file
paths for human-readable previews; normal automated tests need neither.

Rendered previews and widget tests do not measure frame times, memory pressure,
or startup latency on physical devices. Before store release, smoke-test login,
keyboard entry, live draw updates, rotation, screen-reader navigation, and scrolling
on a supported older Android handset and a recent Android/iPhone. No minimum OS
version or distribution/signing settings were changed by this UI work.
